04 / THREE GATES

三道闸门，治理三类复杂度

GATE 01

组织准备度

公司是否装得下 AI？
目标、流程、责任、人员能力与数据基础。
通过标准 → 场景可量化、责任可追溯、结果可验收
GATE 02

Agent 工程

系统能否稳定且经济地运行？
Skill、上下文、工具、重试与结果验证。
通过标准 → 能力按需加载，总成本由验证结果衡量
GATE 03

工作流平台

Agent 能否进入真实业务？
系统连接、企业数据、身份、权限与成果交付。
通过标准 → 在既有权限内端到端交付并沉淀资产

三个闸门相互约束：没有验收标准，工程侧无法优化；结果不稳定，平台不应扩大权限；工作流不闭环，组织看不到真实价值。

VALUE · COST · ADOPTION05 / 14
三道闸门不是线性采购清单，而是一组相互约束的控制系统。组织闸门决定价值，工程闸门决定成本，工作流闸门决定采用。

INFERENCE

不只是 Token 优化

渐进式披露把能力发现、知识获取和执行权限拆开，为路由治理、最小权限和上下文预算提供同一个控制面。

核心原则：只在任务真正需要时，加载足够完成任务的最小能力集合。

L0 INDEX → L4 GOVERNANCE07 / 14
L0 让系统知道有哪些能力；L1 规定如何使用；L2 提供知识；L3 执行确定性动作；L4 负责长期治理。权限也应像上下文一样按阶段激活。

09 / WHY NOW

为什么现在必须治理上下文与 Skill

01

能力数量增长

Skill、MCP、连接器、专家和应用市场不断扩张，误路由的绝对成本随之上升。

02

Agent Loop 变长

任务包含规划、检索、执行、恢复、验证和交付，每一轮都可能继续累积上下文。

03

企业权限扩大

办公 Agent 开始读写文档、表格、会议和审批，加载同时影响安全与业务风险。

04

用量进入治理

组织空间、成员管理和用量控制开始进入产品后台，成本不再只是个人问题。

分层加载将从模型上下文技巧，演变为 Agent Runtime 的基础控制面。
CONTEXT × PERMISSION × COST10 / 14
Why Now 的关键不是上下文窗口不够长，而是企业需要同时控制注意力、权限、成本与责任。
10 / DEEP INSIGHTS

从事实进一步推导出的四个信号

01

组织转型与 Skill 加载遵循相同规律

都需要从最小可行场景开始，以反馈控制复杂度，再逐步扩展。

02

成本治理与质量治理正在合并

更合理的指标同时约束总消耗、验证通过率与错误返工。

03

企业上下文可能成为平台控制点

业务规则、权限、工作流、记忆与评测资产，可能比模型本身形成更高迁移成本。

04

Skill 市场需要从数量市场升级为结果市场

调用、评测、工作流渗透、人工节省和持续付费，比资产总数更重要。

INFERENCE · HYPOTHESIS11 / 14
第三项是待验证假设：标准协议和可迁移格式可能削弱平台锁定。其余三项是基于本周证据的推断。
11 / IMPLICATIONS

从一个可验收流程开始

0–30 DAYS

建立基线

可优先选择一个高频、边界清晰的流程，逐步明确任务集、风险分级和验收方式。

可形成：任务基线、最小 Skill 集合、依赖图、验收参考。

观察点 → 结果已有相对清晰的判断依据
31–60 DAYS

对照观察

可尝试引入 LDR，对比全量与分层加载，持续记录调用、重试、时延和结果。

可形成：对照观察报告、加载日志、典型失败样本。

观察点 → 至少一项指标积极变化，且无明显副作用
61–90 DAYS

逐步固化

可结合前期结果评估是否精简高空加载 Skill，并完善版本、权限、回退和下线机制。

可形成：Skill 注册清单、治理看板、运行指引。

观察点 → 关键指标相对稳定，具备继续推广基础

建议观察：输入 Token、首次成功率、工具调用次数、总时长、独立验证通过率、每次验证通过结果的总成本。

RECOMMENDATION · FLEXIBLE PATH12 / 14
这里使用建议式表达，不把 90 天当成强制计划。不同企业可根据风险、资源与实际效果调整节奏。
12 / COUNTERCASE & RISK

什么情况下，这个判断可能不成立

反方假设

低回报不完全是组织问题场景选择、数据不足和模型能力同样可能是主因。
上下文更少不一定更好过度压缩可能遗漏关键约束，降低首次成功率。
企业上下文未必形成永久锁定开放协议和可迁移格式可能降低切换成本。

主要风险

路由错误错误流程与工具
上下文不足遗漏业务约束
指令冲突停顿与行为漂移
权限扩散越权与数据泄露
过度验证成本与时延失控
数据不可比错误市场排名

最终检验标准：分层加载是否改善真实任务的验证通过率与总成本。

FALSIFIABLE BY DESIGN13 / 14
一个好的洞察需要说明如何被证伪。如果路由错误和上下文不足带来的返工超过收益，分层加载就不应被机械推广。
