模型 · 多模态 · 成本 · 产品体验 / 11.18

一、Gemini 4 Neon：把“选最强模型”改成“选择合适的工作档位”

事实。Google 发布 Neon，面向复杂编程、知识工作与科学工作流；官方列出百万 Token 上下文，以及 API、企业产品与部分付费个人入口。它在 Gemini 4 家族中位于快速日常执行的 Hydrogen 与深度项目推理的 Carbon 之间。标准 API 报价为每百万输入 Token 3 美元、输出 15 美元，缓存输入 0.15 美元。开始推出不代表每个地区、账号与界面同步出现。[1] Google｜Gemini 4 Neon

技术展开：长上下文、思考预算与执行循环是三件事

长上下文决定一次能放进多少材料，不能保证模型优先采用最新版本、正确识别冲突或找到全部证据。分析多厂商纪要时，仍应给文件标日期、厂商、版本与来源位置，再检查旧结论是否被新记录覆盖。把历史资料全部塞入上下文，也可能增加无关信息和输入成本。

“更快完成”需要观察整个任务：读取材料 → 规划 → 调用工具 → 检查结果 → 修改交付。某一步生成更快，可能被更多重试抵消。对于中途纠正，关键体验是模型能否只修改受影响的步骤，并保留已经确认的内容。Google 将可引导性与多步指令遵循作为卖点；其排名与内部低虚构率说明属于评测证据，不能直接替代团队材料上的准确率。未公开的模型规模、训练配方与路由内部实现，本文不作推测。

更新前后：模型入口与完成标准分别比较

对照项已有路径本周变化体验问题
模型选择Hydrogen 面向日常执行；Carbon 面向更深任务Neon 增加中间档位用户能否理解何时切换，而不是只看到新名字？

竞争与商业：分档让路由更有价值，也增加采购复杂度

判断：高频流程可以先把任务拆成材料提取、争议判断和最终验收，再分别设质量门槛。提取用较低成本档位，冲突交给更强模型，是待验证的设计假设；多一次模型交接也会增加上下文整理和错误传播成本。模型更多，不自动等于总费用更低。

体验关注点从“回答像不像专家”扩展到“是否记住修订、是否保留引用、是否交付可编辑文件”。若产品只提供模型切换按钮，却没有显示材料范围、执行状态和费用，用户仍难判断该在哪一步升级。

对我们业务有什么影响

结合工作区“多厂商周会 → 待办台账 → 人工确认”的既有场景，可用同一批脱敏纪要对照提取与冲突处理。先保留人工验收，不直接写回正式台账。团队账号可用性尚未知；以上为试点建议。

产品 · 企业知识 · 团队协作 / 11.17

二、Ignite：工作空间、企业上下文和成本管理被放到同一条链上

事实。微软在 Ignite 介绍 Copilot Workspaces、Microsoft IQ 和 Agent 365 Business Analytics，分别指向人和 Agent 的共享工作、企业上下文复用及成本与结果的可见性。不同功能的具体开放范围应逐项查产品文档，本文不将大会介绍统一标成全面可用。[3] Microsoft｜Ignite 主旨 [4] Microsoft｜Ignite 产品总览

技术展开：共享聊天记录，还不足以支持团队协作

团队任务需要至少维护四类对象：原始证据、当前工作版本、执行中的动作、已经批准的结论。聊天是讨论过程，任务状态则需要明确的负责人、状态转换和验收条件。例如某厂商截止日期改动后，系统应知道要更新哪条待办、保留哪份历史记录，以及哪些下游提醒需要重算。

下面是实施建议，并非微软披露的内部架构：

证据与权限 → 版本化上下文 → 任务状态与工具执行 → 可编辑成果 → 独立验收与费用归集

上下文复用也要处理撤权与过期。共享插件或连接器能读取数据，不等于它可以把数据转发给所有协作者。应在读取和写回时分别检查身份与范围；任务日志只记录必要字段，避免把敏感正文复制到每层日志。执行恢复时，应区分“尚未执行”和“执行结果未知”：后者先查外部系统，再决定是否重试，防止重复创建记录。

从单人交办到共享项目，变化在哪里？

微软主旨将此前以个人 Agent 循环为主的使用方式，与此次共享工作空间作对照。对于用户，变化在于任务可围绕共同目标和上下文组织；是否支持具体的并发编辑、细粒度审批和冲突处理，仍需产品文档与账号验证。本文不把“共享空间”解释成所有成员天然共享全部数据，也不将发布会演示视为完整上线记录。

差异与产业：企业知识成为持续维护的产品资产

判断：相较单次生成工具，工作空间的竞争力更依赖版本、权限、成果格式和已有业务系统连接。知识接入、流程维护、验收规则将成为交付工作的一部分。原始资料可以导出，也不代表权限、状态、技能和历史成果能完整迁移；采购应分别核对。

成本看板提供观察入口，但“使用次数”“辅助小时”与业务节省工时口径不同。只有计入人工核对、失败重跑、集成与维护，才能比较替代现有流程后的净收益。本文不根据大会客户规模推算市场收入或算力需求。

对我们业务有什么影响

可以围绕现有周会台账建立证据 ID、记录版本与人工确认状态。这些基础字段比增加一个聊天入口更能改善跨人交接。若评估外部平台，要求演示旧资料撤权、已完成任务复查和成果导出；暂无本团队生产测试结果。

技术展开：项目指令是上下文，不是权限系统

AGENTS.md 可以承载模板、命名规则与工作约束。它会影响模型行为，但不能代替文件访问控制、企业角色权限或外部写入审批。一个能读到其他厂商机密材料的工具，不会因为指令写了“不要泄露”就获得可靠隔离。应分别核对规则被读取的时机、作用范围，以及工具在执行时真正检查的权限。

后台任务还引入状态一致性问题：主会话要求修改截止日期，分叉却仍在使用旧日期时，最终结果以哪个版本为准？可选工程设计是给输入与成果附版本号，写回时检测冲突，再由用户决定合并。官方日志并未说明其内部采用这种方案，不能将建议写成产品已有保证。

03 / 我的判断

本期判断：把模型升级转成可验证的交付改进

  1. 模型分层会增加流程设计价值。判断依据是新模型明确强调速度、复杂度和使用入口的差异；是否实际省钱，仍需同任务对照。不要每周重写整套流程，先固定数据和验收，再更换一个变量。
  2. 企业知识的质量与权限将影响协作体验。共享上下文有助于减少搬运材料，但过期信息、冲突版本与权限泄漏可能随复用扩散。接入量只是规模指标。
  3. 交付成功应由模型外部证据确认。文件存在、字段正确、引用可回溯、外部状态符合预期，才构成验收。模型自述“已完成”不能单独证明结果。

可参考的验证方法：以一条完整流程观察实际效果

评估此类产品时，可以选取历史周会的脱敏材料，覆盖日期冲突、责任人缺失与跨厂商边界等情况。以可编辑待办表作为统一输出，由人工预先标注关键字段，再对照人工处理与模型方案，记录遗漏、错误、修改时间、总费用和最终通过验收的任务数。成本可按“全部试验消耗与人工成本 ÷ 最终通过验收的任务数”计算，并注明人工单价假设。上述方法可根据实际场景与测试条件选用，本文尚未执行相关测试。

贯穿案例｜三家厂商周会，怎样变成可确认的待办？

以下全部是虚构的验收场景，不是已运行的客户案例。输入包含 A、B、C 三家厂商各两期纪要、旧待办表和一份字段规范。旧纪要写 A 厂商周五交付，新纪要改为下周二；B 厂商某项任务没有责任人；C 厂商附件只允许项目组读取。目标是生成可编辑台账和一页汇报，正式发布由人确认。

环节系统应完成什么用户应能看见什么失败判据
1 接入与分组标注厂商、会议日期、文件版本与权限本轮使用的材料清单把 C 的受限附件送入共享空间
2 提取与判断抽取事项，识别 A 的日期变更；B 保持待确认每条记录能回到原文位置凭空补 B 的责任人，或保留 A 的旧日期
3 生成与局部修改产生表格和汇报；只修改指定字段修改前后差异与待确认项修改 A 时覆盖了已确认的 C 记录
4 审核与写回获批后更新指定记录，保留历史批准人、写入目标、结果回执把生成草稿误当成已发布成果
5 异常与恢复回执丢失后先查状态，避免重复失败原因、已完成步骤、可继续范围直接重跑导致重复创建事项

与本期更新的关系：Neon 可作为提取与冲突判断的候选模型；Workspaces 类产品提供协作入口；Kimi 项目规则与文件交付可作为单人工作台候选。它们不是本文已经接通的一套系统，也不假定任意两家可直接互操作。安全控制和正式写回必须另行验收。

验收建议：先由人标注正确待办，分别统计必填字段、关键事项遗漏、来源正确性、非目标内容变更和编辑分钟数。第一次只生成草稿；草稿验收通过后，再单独测试写回与恢复。关键权限越界出现一次即停止该轮测试，修复后重跑。

技术展开：内容拒答与执行控制应分别验收

内容层检查模型是否识别危险意图；工具层检查系统是否允许读取、上传或修改具体资源；运行层检查凭据、网络出口和隔离边界；业务层检查谁能批准外部动作。某一层改进不能替代其余层。安全测试还要覆盖多轮对话、外部文档夹带指令、权限变化和异常恢复，而不能只看一条标准提示词是否被拒绝。

报告提供的是特定时间与条件下的风险证据，不是所有日常任务的风险发生率，也不能据此认定每个后续版本都存在相同缺陷。本文仅讨论评估方法，不复述有害方案或绕过细节。

商业影响：可控性需要进入交付承诺

判断：企业客户会更需要版本记录、权限清单、操作回执和事故处置能力。安全投入能否形成采购优势仍需合同与客户证据，不能仅凭监管新闻推断需求增长。对外承诺“全程可控”前，应明确哪些动作被阻断、哪些需要确认、异常后如何查询结果。

对我们业务有什么影响

对现有资料整理流程，优先覆盖跨厂商资料误共享、外部文档指令干扰、重复写入三类风险。测试使用脱敏材料和模拟端点，保留人工发布。没有生产事故记录，不能报告实际风险下降百分比。
